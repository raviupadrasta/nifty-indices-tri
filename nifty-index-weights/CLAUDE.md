# nifty-index-weights — NSE/Nifty index constituent weights

Fetches published index compositions from niftyindices.com and stores them as dated CSVs, so
index weights can be tracked over time.

## How it works

Source: `liveindexsa.niftyindices.com` publishes each index's sector/stock composition as a JSONP
file at `jsonfiles/Sector/SectorialIndexData<NAME>_Sector.js`, where `<NAME>` is **uppercased**
(case-sensitive endpoint — lowercase/mixed-case 404s). Inconsistently, `<NAME>` is sometimes the
abbreviated `IndexTradingname` and sometimes the full `Title` from the master list — e.g. `NIFTY
FIN SERVICE` 404s but `NIFTY FINANCIAL SERVICES` (its Title) works. Additionally, a literal `%` in
the Title is dropped rather than percent-encoded (`"...25% Cap"` -> URL `"...25 CAP"`, not
`...25%25 CAP`). And at least one index (`Nifty India Internet & E-Commerce`) is published under a
name with no derivable relationship to either field (`NIFTY INDIA INTERNET`, found by trial and
error) — handled via the hand-verified `NAME_OVERRIDES` dict, not a heuristic (don't add entries by
guessing; confirm a 200 first). `fetch_composition_for_entry()` tries, in order: `IndexTradingname`,
`Title`, `Title` with `%` stripped, then any `NAME_OVERRIDES` entry — and reports which candidate
worked (`via '...'` in the OK line). The response wraps a JS object (not strict JSON — has trailing
commas) in `modelDataAvailable(...)`.

The master list of all indices (name, title, category, short code) is at
`jsonfiles/IndexType.json` — refresh it with `--list`, cached at `reference/index_type.json`.

Even after the Title fallback, not every index has published composition data — Government
Securities, Money Market, SDL, Target Maturity, Fixed Income, and Hybrid indices are skipped
entirely (this endpoint has no stock composition to publish for debt instruments), as are a
handful of derivative-based equity indices (arbitrage, leveraged/inverse, futures-tracking — e.g.
`NIFTY 50 ARBITRAGE`, `NIFTY50 PR 2X LEV`) for the same reason. The fetch script treats these as
skips, not errors — check run output for `SKIP` lines, or `reference/skipped_indices.txt` for the
full current list, rather than assuming a bulk fetch got everything.

## Files

- `scripts/fetch_index_weights.py` — the fetcher. `--list` refreshes the master index list;
  otherwise pass index names positionally, via `--file`, or `--category`. See its docstring/`--help`
  for full usage.
- `reference/index_type.json` — cached master index list (regenerated by `--list`).
- `reference/indices.txt` — editable watchlist of index names for repeat fetches.
- `data/<INDEX_NAME>_<DD-MM-YYYY>.csv` — one file per index per as-of date, columns: `sector,
  sector_weight, symbol, weight, as_of_date`. Filenames use the source's own as-of date, not the
  fetch date, so re-running before the index provider updates just overwrites the same file.

## Conventions

- Pure stdlib (urllib/json/csv/re) — no dependencies to install.
- Re-running is safe/idempotent: output filename is keyed on the data's own as-of date.
